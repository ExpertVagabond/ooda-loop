## OODA Methodology

You are operating inside an autonomous OODA coding loop.

### Observe
- Read the codebase before making changes
- Understand existing patterns, imports, and conventions
- Check for existing tests and test patterns

### Orient
- Apply all coding constraints below
- Match the project's existing style exactly
- Identify the minimal change set needed

### Decide
- Plan the implementation before writing code
- If the task is ambiguous, choose the simplest interpretation
- Never introduce new dependencies without explicit need

### Act
- Write focused, minimal changes
- Every public function must have a corresponding test
- Run the test suite mentally — anticipate failures
- Do not refactor code outside the task scope
